# Диаграммы и зависимости

> Актуализировано под текущую реализацию (Python + PyQt6). Дата: 2026-07-11.
> Диаграммы отражают фактические классы и связи в коде.

## 1. Диаграмма зависимостей слоёв

```
┌──────────────────────────────────────────────────────────────┐
│  Presentation (PyQt6)                                         │
│  MainWindow · AsyncWorker(QThread) · CollapsibleGroupBox      │
└───────────────┬──────────────────────────────────────────────┘
                │ вызывает сервисы (через AsyncWorker)
                ▼
┌──────────────────────────────────────────────────────────────┐
│  Application (services)                                       │
│  MeetingService · TranslationService · TemplateService ·      │
│  CostEstimatorService                                         │
└───────────────┬───────────────────────────┬──────────────────┘
                │ зависит от контрактов      │ использует реализации
                ▼                            ▼
┌───────────────────────────┐   ┌──────────────────────────────┐
│  Domain                   │◄──│  Infrastructure              │
│  entities · interfaces ·  │реализует audio · openai ·        │
│  enums                    │   │  repositories · storage ·     │
│                           │   │  file_system                  │
└───────────────────────────┘   └──────────────────────────────┘

        Core (кросс-слойно): logging · exceptions · health
```

Правило: **Domain ни от кого не зависит.** Application зависит от Domain.
Infrastructure реализует интерфейсы Domain. Presentation зависит от Application.
Core доступен всем.

## 4. Sequence: запись совещания (старт → стоп → сохранение)

```
Пользователь   MainWindow        MeetingService     MeetingAudioRecorder     Диск
    │  «Записать»   │                   │                    │                 │
    ├──────────────►│                   │                    │                 │
    │               │ start_meeting()   │                    │                 │
    │               ├──────────────────►│ Meeting.create()   │                 │
    │               │                   │ .start() (RECORDING)│                 │
    │               │◄──────────────────┤ (сохранён)          │                 │
    │               │ get_recording_path()                    │                 │
    │               │ start_recording(path, mic, system, …)   │                 │
    │               ├────────────────────────────────────────►│ откр. .mic.pcm  │
    │               │                   │                    │ откр. .sys.pcm  │
    │  индикатор ●  │◄─── on_meeting_started (таймер, авто-стоп)                │
    │   таймер идёт │                   │   callbacks пишут ──►│ .pcm растут ───►│
    │               │                   │                    │                 │
    │  «Стоп»       │                   │                    │                 │
    ├──────────────►│ stop_meeting()    │                    │                 │
    │               ├──────────────────►│ stop_recording()   │                 │
    │               │                   ├───────────────────►│ стоп потоков    │
    │               │                   │                    │ _stream_mix_to_wav
    │               │                   │                    │ .pcm ──поблочно──► .wav
    │               │                   │                    │ удалить .pcm    │
    │               │                   │◄───────────────────┤ путь WAV        │
    │               │                   │ MeetingRecording.create/save         │
    │               │                   │ meeting.stop() (STOPPED)              │
    │  путь файла   │◄─── on_meeting_stopped (_reset_recording_ui)             │
    │   показан     │                   │                    │                 │

Ошибка сохранения → on_meeting_stop_error: сброс UI, .pcm остаются на диске,
совещание всё равно помечается STOPPED (не залипает).
```

## 7. State: жизненный цикл `Meeting`

```
        create()
           │
           ▼
     ┌─────────────┐  start()   ┌───────────┐  stop()   ┌──────────┐
     │ NOT_STARTED │───────────►│ RECORDING │──────────►│ STOPPED  │
     └─────────────┘            └───────────┘           └────┬─────┘
                                                             │ mark_processing()
                                                             ▼
                                                        ┌────────────┐
                                                        │ PROCESSING │
                                                        └─────┬──────┘
                                                              │ mark_completed()
                                                              ▼
                                                        ┌────────────┐
                                                        │ COMPLETED  │
                                                        └────────────┘

Восстановление при старте (main): если найден Meeting в RECORDING (после сбоя/
краха) — рекордер останавливается и meeting переводится в STOPPED.
```

## 9. Потоки выполнения (threads)

```
Главный поток (Qt UI event loop)
   │
   ├─ AsyncWorker #1 (QThread) ── asyncio loop ── start/stop_meeting, generate_report, recover
   ├─ AsyncWorker #2 (QThread) ── переводы
   │
Аудио-потоки (во время записи совещания):
   ├─ PortAudio callback-поток (микрофон)  → пишет .mic.pcm
   └─ soundcard loopback-поток (threading.Thread, daemon) → пишет .sys.pcm

Синхронизация буферов/файлов — через Lock (_mic_lock, _sys_lock).
Тяжёлое сведение при «Стоп»/восстановлении вынесено в поток (не блокирует UI).
```
