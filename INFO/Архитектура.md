# Архитектура приложения MeetingAssistant

> Актуализировано под текущую реализацию (Python + PyQt6). Дата: 2026-07-11.
> Прежняя версия описывала непостроенный вариант на C#/.NET/WPF.

## Общая концепция

Приложение построено по принципам **Clean Architecture**: слои `domain`,
`application`, `infrastructure`, `core`, `presentation`. Зависимости направлены
внутрь — к домену; внешние детали (аудио, HTTP, файлы, GUI) вынесены в
инфраструктуру и презентацию. Граф зависимостей собирается вручную (Dependency
Injection) в `main.py::setup_dependencies()`.

---

## 1. Domain Layer (`domain/`)

Бизнес-сущности и контракты, независимые от внешних библиотек.

### 1.1. Entities (`domain/entities/`)

**`Meeting`** (`meeting.py`, `@dataclass`) — агрегат совещания.
- Поля: `id: UUID`, `start_time: datetime`, `end_time: Optional[datetime]`,
  `status: MeetingStatus`, `recording_path`, `report_path`, `template_path`,
  `transcription_path`.
- Методы жизненного цикла: `create()` → `NOT_STARTED`; `start()` → `RECORDING`;
  `stop()` → `STOPPED` (+`end_time`); `mark_processing()` → `PROCESSING`;
  `mark_completed()` → `COMPLETED`.

**`MeetingRecording`** (`meeting_recording.py`) — метаданные WAV.
- Поля: `id`, `meeting_id`, `file_path`, `duration_seconds`, `file_size_bytes`,
  `created_at`, `sample_rate=44100`, `channels=2`. Свойство `exists`.

**`MeetingReport`** (`meeting_report.py`) — сгенерированный отчёт: `content`,
`language: Language`, `template_path`, `created_at`.

**`TranslationResult`** (`translation_result.py`) — результат перевода:
`original_text`, `translated_text`, `source_language`, `target_language`.

**`ExampleTemplate`** (`example_template.py`) — шаблон-пример: `file_path`,
`content`, `file_type` (`txt`/`docx`), `loaded_at`.

### 1.2. Interfaces (`domain/interfaces/`)

- **`IAudioRecorder`** (`typing.Protocol`) — контракт рекордера. Атрибуты
  `sample_rate`, `channels`, `is_recording`; методы `start_recording(output_path, **kwargs)`,
  `stop_recording() -> str`, `get_audio_level() -> float`.
- **`IMeetingRepository`** (ABC) — `save`, `get_by_id`, `get_all`, `get_current` (async).
- **`IRecordingRepository`** (ABC) — `save`, `get_by_meeting_id`, `get_all` (async).
- **`IReportRepository`** (ABC) — `save`, `get_by_meeting_id`, `get_all` (async).
- **`ITemplateRepository`** (ABC) — `save`, `get_current` (async).

### 1.3. Enums (`domain/enums/`, все `(str, Enum)`)

- **`Language`** — `RUSSIAN`, `POLISH`, `ENGLISH`; свойства `code` (`ru/pl/en`),
  `display_name` (`Русский/Polski/English`).
- **`MeetingStatus`** — `NOT_STARTED`, `RECORDING`, `STOPPED`, `PROCESSING`, `COMPLETED`.
- **`AudioSourceType`** — `MICROPHONE`, `STEREO_MIX`.
- **`TranslationStatus`** — `IDLE`, `LISTENING`, `PROCESSING`, `COMPLETED`, `ERROR`.

## 2. Application Layer (`application/services/`)

Оркестрация сценариев поверх домена и инфраструктуры.

### `MeetingService` (`meeting_service.py`)
Зависимости (через конструктор): `IMeetingRepository`, `IRecordingRepository`,
`IAudioRecorder`, `StorageService`, `OpenAIClient`.
- `async start_meeting()` — если уже идёт запись → `MeetingAlreadyStartedException`;
  иначе `Meeting.create()`, `start()`, сохранение. **Старт самого рекордера
  происходит из UI** (там формируется путь файла).
- `async stop_meeting()` — берёт текущее совещание; `audio_recorder.stop_recording()`;
  длительность вычисляется из размера файла (16-bit PCM); создаётся и сохраняется
  `MeetingRecording`; `meeting.stop()`. **Устойчивость:** при ошибке сохранения
  совещание всё равно помечается `stop()` (не «залипает» в `Recording`), а
  исключение пробрасывается в UI.
- `async attach_transcript(meeting_id, path, text)` — проставляет `transcription_path`.
- `async process_meeting(meeting_id, target_language, template_content, transcript_text)`
  — валидация статуса (`Stopped`/`Completed`) → `mark_processing()` →
  `CostEstimatorService.estimate()` (лог токенов) → `OpenAIClient.generate_report()`
  → `StorageService.save_report()` + `save_final_report_json()` → `mark_completed()`.
  **Транскрипция здесь НЕ выполняется** — только «текст + шаблон → GPT».

### `TranslationService` (`translation_service.py`)
Зависимости: `AudioRecorder`, `OpenAIClient`, `StorageService`.
- `async translate_from_audio_file(file_path, source_type, target_language, source_language=None)`
  — `transcribe_audio()` → `translate_text()` → `TranslationResult.create()`;
  временный файл удаляется в `finally`.

### `TemplateService` (`template_service.py`)
Зависимости: `ITemplateRepository`, `FileParserFactory`.
- `async load_template(file_path)` — парсит `.txt`/`.docx`, создаёт `ExampleTemplate`, сохраняет.
- `async get_current_template()`.

### `CostEstimatorService` (`cost_estimator_service.py`)
Без внешних вызовов. `estimate(*, input_text, expected_output_tokens=2000) -> TokenEstimate`
— эвристика ≈4 символа/токен. `TokenEstimate` (frozen dataclass): `input_tokens`,
`output_tokens`, `total_tokens`.

## 3. Infrastructure Layer (`infrastructure/`)

### 3.1. Audio (`external_services/audio/`)

**`MeetingAudioRecorder`** — основной рекордер совещаний, реализует `IAudioRecorder`.
Ключевая особенность — **потоковая запись на диск** (устраняет потерю длинных
записей и рост памяти):

- **Старт** (`start_recording`): микрофон через `sounddevice.InputStream`
  (моно int16, callback пишет байты в `<output>.mic.pcm`); системный звук —
  приоритетно **WASAPI loopback через `soundcard`** в отдельном потоке (пишет в
  `<output>.sys.pcm`), fallback — входное устройство Stereo Mix. Аудио пишется на
  диск по мере поступления; в памяти держится только последний блок (для индикатора
  уровня).
- **Стоп** (`stop_recording`): останавливает потоки, закрывает `.pcm`, затем
  `_stream_mix_to_wav()` **поблочно** сводит два mono-PCM файла в стерео 16-bit WAV
  (блок `_MIX_BLOCK_FRAMES = 1_048_576` кадров). Каждая запись в WAV ≤ ~4 МБ —
  исключает одиночную запись >2 ГБ (Windows `[Errno 22]`). Учитывается лимит RIFF
  (`_WAV_MAX_DATA_BYTES ≈ 4.2 ГБ`): при превышении файл валидно финализируется, а
  сырые `.pcm` сохраняются для восстановления. При успехе `.pcm` удаляются; при
  ошибке — остаются (данные восстановимы).
- **Сведение**: `mix_mono_blocks_to_stereo_int16()` — ядро (выравнивание длин
  тишиной, гейны, клиппинг, дублирование в стерео); `mix_sources_to_stereo_int16()`
  — обёртка над списками чанков (для тестов и индикатора уровня).
- `get_audio_level()` — RMS 0–100 по последним блокам.

**`AudioRecorder`** — запись одного источника (используется `TranslationService`).
Пишет чанки в память, при стопе конкатенирует и сохраняет WAV. Авто-подбор
устройства; исключает Stereo Mix при выборе микрофона.

**`LoopbackRecorder`** — запись системного выхода через WASAPI loopback (`soundcard`),
API-совместим с `AudioRecorder`.

### 3.2. OpenAI (`external_services/openai/`)

**`OpenAIClient`** — HTTP-клиент к OpenAI через `aiohttp`.
- Параметры из env: `OPENAI_BASE_URL`, `OPENAI_MODEL` (`gpt-4`),
  `OPENAI_TRANSCRIPTION_MODEL` (`whisper-1`), `OPENAI_MAX_TOKENS`, `OPENAI_TEMPERATURE`,
  ретраи.
- `_make_request()` — запросы с ретраями и ротацией ключей из пула, обработка 429.
- `transcribe_audio()` (whisper, для переводов), `translate_text()`,
  `chat_completion()`, `generate_report(transcription, template, language)`.

**`ApiKeyPool`** — пул ключей `OPENAI_API_KEY_1..3` (или единый `OPENAI_API_KEY`).
Балансировка по наименьшей загрузке, временная блокировка при сбое/429, статистика.
Контекст-менеджер `acquire_key()`. При отсутствии ключей — `ApiKeyNotFoundException`.

### 3.3. Repositories (`repositories/`)
- **`MeetingRepository`** — in-memory + сериализация в `./Config/meetings.json`;
  хранит текущее совещание (`get_current`).
- **`RecordingRepository`**, **`ReportRepository`**, **`TemplateRepository`** — in-memory.

### 3.4. Storage (`storage/storage_service.py`)
`StorageService` — единая точка формирования путей и сохранения:
`get_recording_path()`, `get_report_path()`, `get_final_report_json_path()`,
`save_report()`, `save_final_report_json()`, `get_temp_audio_path()`. Создаёт все
рабочие каталоги при инициализации.

### 3.5. File System (`file_system/file_parser.py`)
`IFileParser` (ABC) → `TextFileParser` (`.txt/.md/.log`, UTF-8 с fallback),
`WordFileParser` (`.docx` через `python-docx`); `FileParserFactory` подбирает парсер.

## 4. Core Layer (`core/`)

- **`logging/logger.py`** — `AppLogger` (singleton), логгер `"MeetingAssistant"`:
  консоль (INFO) + `RotatingFileHandler` (`Logs/app_{YYYY-MM-DD}.log`, 10 МБ × 5,
  DEBUG). Доступ через `get_logger()`.
- **`exceptions/`**:
  - `ApiException` → `ApiKeyNotFoundException`, `ApiRateLimitException`, `ApiRequestException`.
  - `MeetingException` → `MeetingAlreadyStartedException`, `MeetingNotStartedException`, `MeetingNotStoppedException`.
  - `TranslationException` → `TranslationFailedException`, `AudioCaptureException`.
- **`health/health_checker.py`** — `HealthChecker.check_all()`: проверки OpenAI API,
  микрофона, динамиков (через `soundcard`), рабочих папок и зависимостей;
  `get_summary()`.

## 5. Presentation Layer (`presentation/main_window.py`)

**GUI:** PyQt6 (`QMainWindow`, виджеты, `QTimer`, сигналы `pyqtSignal`).
Windows-специфика через `ctypes` — скрытие окна из захвата экрана
(`WDA_EXCLUDEFROMCAPTURE`) и панели задач (`WS_EX_TOOLWINDOW`).

**Фоновая модель:** `AsyncWorker(QThread)` оборачивает корутину — создаёт event loop,
`run_until_complete()`, эмитит `finished(object)` / `error(str)`. Каждый сервисный
вызов — отдельный воркер; список воркеров в `self.workers`, `closeEvent` их дожидается.
Так тяжёлые операции (старт/стоп, генерация отчёта, восстановление) не блокируют UI.

**`CollapsibleGroupBox`** — сворачиваемые секции интерфейса.

**Функциональные блоки `MainWindow`:**
- **Запись совещания:** `start_meeting` / `stop_meeting`, обработчики
  `on_meeting_started` / `on_meeting_stopped` / `on_meeting_stop_error`; единый сброс
  UI `_reset_recording_ui()` (гасит таймер/индикатор и при успехе, и при ошибке);
  таймер `update_recording_timer` с обратным отсчётом; **авто-стоп по таймеру**
  (`_apply_auto_stop_selection`, комбобокс `combo_auto_stop`); **восстановитель**
  `recover_recording` (сборка WAV из `.mic.pcm`/`.sys.pcm`).
- **Транскрипт и отчёт:** `load_transcript` (загрузка `.txt` из Colab),
  `load_template`, `generate_report`; кнопка ОТЧЁТ активна только при наличии и
  транскрипта, и шаблона (`_update_generate_report_enabled`).
- **Переводы:** `toggle_translation_recording` (параллельная запись «Выслушать нас» /
  «Выслушать собеседника»), `_stop_translation_recording`, `on_translation_completed`.
- **Аудиоустройства:** выбор микрофона / устройства вывода / режима записи, `check_audio_level`.
- **Управление окном:** прозрачность, «поверх всех», скрытие из захвата/панели задач.

## 6. Точка входа и DI (`main.py`)

`setup_dependencies()` строит граф (упрощённо):

```
StorageService → используется MeetingService и TranslationService
ApiKeyPool → OpenAIClient
MeetingAudioRecorder → MeetingService.audio_recorder   (совещания)
AudioRecorder        → TranslationService.audio_recorder (переводы)
FileParserFactory    → TemplateService
Repositories (Meeting/Recording/Template) → соответствующие сервисы

MeetingService(meeting_repo, recording_repo, meeting_audio_recorder, storage, openai)
TranslationService(audio_recorder, openai, storage)
TemplateService(template_repo, file_parser_factory)

→ возвращает (meeting_service, translation_service, template_service)
```

`main()`: `load_dotenv()` → `get_logger()` → `HealthChecker().check_all()` (при 0
пройденных — критический выход; при частичном — предупреждение) → `QApplication`
→ `setup_dependencies()` → **восстановление зависшего совещания** (если
`meeting_repository.get_current()` в статусе `Recording` — останавливает рекордер и
`meeting.stop()`) → `MainWindow(...)` → `show()` → `app.exec()`.

> Примечание: `ReportRepository` и `LoopbackRecorder` создаются/существуют, но в
> текущем DI-графе никуда не внедряются (отчёты сохраняются напрямую через
> `StorageService`).

## 7. Ключевые архитектурные решения

- **Потоковая запись на диск** (а не буфер в RAM) — надёжность длинных записей,
  быстрый «Стоп», сохранность данных при сбоях. См.
  [КАК_РАБОТАЕТ_ЗАПИСЬ_И_ВОССТАНОВЛЕНИЕ.txt](./КАК_РАБОТАЕТ_ЗАПИСЬ_И_ВОССТАНОВЛЕНИЕ.txt).
- **Транскрипция вне приложения** (Google Colab) — приложение работает с готовым
  текстом транскрипта, снижая стоимость и нагрузку.
- **Пул ключей OpenAI** — устойчивость к лимитам (429) и распределение нагрузки.
- **AsyncWorker поверх QThread** — асинхронные сервисы в синхронном Qt-UI без фризов.
- **Единый сброс UI записи** — устранение рассинхронизации таймера и состояния.
